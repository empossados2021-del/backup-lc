## 1. Objetivo

Adicionar suporte à coleta de configuração de roteadores Mikrotik RouterOS via SSH, usando o driver Netmiko `mikrotik_routeros` e o comando `/export compact`.

## 2. Escopo

### 2.1 Correção de bug — username ignorado

`runner.py` atualmente passa `username="user"` hardcoded ao `ConnectHandler`, ignorando o campo `username` da credencial cadastrada. Esta spec corrige isso.

### 2.2 Driver `mikrotik_routeros`

Entrada adicionada ao `DRIVER_REGISTRY` em `collector/driver.py`:

| Parâmetro | Valor |
| --- | --- |
| `netmiko_type` | `"mikrotik_routeros"` |
| `commands` | `["/export compact"]` |
| `min_chars` | `200` |
| `volatile_patterns` | nenhum (a ser refinado com dados reais) |
| `end_marker` | nenhum |
| `error_patterns` | `["bad command", "syntax error", "failure:"]` |

O comando `/export compact` exporta toda a configuração do RouterOS sem comentários e sem valores padrão, gerando saída compacta e determinística ideal para diff.

### 2.3 O que não entra nesta etapa

- Suporte à API RouterOS (porta 8728/8729): mais complexo, avaliado após validação SSH.
- Outros comandos complementares (`/system resource print`, `/ip address print`).
- Remoção de linhas voláteis (timestamps, uptime): avaliado com dados reais do piloto.

## 3. Testes

- `get_driver_spec("mikrotik_routeros")` retorna o spec correto.
- Coleta simulada com Netmiko mockado passa username correto da credencial.
- Saída com menos de 200 chars falha validação (SAIDA_INCOMPLETA).
- Saída contendo `"bad command"` falha validação.
- Coleta bem-sucedida com saída válida retorna `status="ok"`.

## 4. Critérios de aceite

- [x] `get_driver_spec("mikrotik_routeros")` não levanta exceção.
- [x] Coleta de dispositivo `mikrotik_routeros` usa username real da credencial.
- [x] Todos os testes existentes continuam passando.
