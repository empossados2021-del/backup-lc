# Spec E7.1 — Histórico de coletas

| Campo | Valor |

## 1. Objetivo

Dar visibilidade sobre os ciclos de coleta — automáticos e manuais — para que o operador consiga confirmar se os agendamentos rodaram, quantos dispositivos foram coletados e se houve falhas, sem precisar consultar logs do container.

## 2. Escopo

### 2.1. Página de histórico (`GET /history`)

Nova rota acessível a todos os perfis autenticados (reader+).

**URL:** `GET /history?page=N&trigger=<filtro>&status=<filtro>`

**Exibição em dois níveis:**

#### Nível 1 — Ciclos

Cada ciclo agrupa todas as execuções disparadas dentro de uma janela de 1 minuto com o mesmo `trigger`.
Colunas da tabela:

| Coluna | Descrição |
| --- | --- |
| Data / Hora | `started_at` do ciclo (formatado em UTC-3 / fuso configurado) |
| Origem | `Agendado` ou `Manual` |
| Dispositivos | Total de dispositivos no ciclo |
| Concluídos | Contagem de `status = "ok"` |
| Falhas | Contagem de status ≠ `"ok"` ≠ `"running"` |
| Em andamento | Contagem de `status = "running"` |
| Duração | Diferença entre o último `ended_at` e o primeiro `started_at` do ciclo |

Paginação: 20 ciclos por página, do mais recente ao mais antigo.
Filtro por `trigger` (`all` / `scheduled` / `manual`) via `<form method="get">` com `<select>`.

#### Nível 2 — Detalhe do ciclo (`GET /history/<timestamp_iso>?trigger=<valor>`)

Lista todas as execuções do ciclo selecionado.
Colunas:

| Coluna | Descrição |
| --- | --- |
| Dispositivo | Nome do switch (link para `/devices/{id}`) |
| Iniciado | `started_at` formatado |
| Duração | Tempo da execução individual |
| Status | Badge com cor: `ok` (verde), `running` (cinza), demais (vermelho) |
| Detalhe | Primeira linha do `failure_detail` JSON se houver |

Sem paginação no detalhe (ciclos têm poucos dispositivos).

### 2.2. Link no menu de navegação

Novo item "Histórico" no `base.html`, visível a todos os perfis autenticados.
Ícone: relógio SVG (inline, sem arquivo externo).

### 2.3. Serviço de histórico (`history/service.py`)

```
get_cycles(db, page, per_page, trigger_filter) -> list[CycleSummary]
count_cycles(db, trigger_filter) -> int
get_cycle_executions(db, started_at_window, trigger) -> list[ExecutionRow]
```

- `CycleSummary`: dataclass com os campos da tabela de ciclos
- `ExecutionRow`: dataclass com device_name, started_at, ended_at, status, failure_detail
- Agrupamento de ciclos: `DATE_TRUNC` equivalente — agrupa execuções por `(trigger, floor(started_at / 60s))`; em SQLite usa `strftime('%Y-%m-%dT%H:%M', started_at)` como chave de agrupamento
- Sem ORM complexo: consultas SQL diretas via `db.session()` com `text()`

### 2.4. CSS

Novo badge de status reutilizável em `app.css`:

```css
.badge          /* base */
.badge--ok      /* verde */
.badge--error   /* vermelho */
.badge--running /* cinza */
```

| Tipo | O que cobre |
| --- | --- |
| Unit | `get_cycles`: agrupa execuções do mesmo minuto no mesmo ciclo |
| Unit | `get_cycles`: ciclos de minutos diferentes ficam separados |
| Unit | `get_cycles`: filtro `trigger=scheduled` exclui manuais |
| Unit | `get_cycles`: paginação — página 2 retorna ciclos corretos |
| Unit | `get_cycle_executions`: retorna todas as execuções do ciclo com nome do device |
| Unit | `count_cycles`: conta correto com e sem filtro |
| Integration | `GET /history` (reader) → 200, tabela de ciclos no HTML |
| Integration | `GET /history` sem autenticação → redirect para `/login` |
| Integration | `GET /history?trigger=scheduled` → só ciclos agendados |
| Integration | `GET /history/<ts>?trigger=scheduled` → execuções do ciclo |
